`tmp/` is disposable in its entirety. No retained log, executable, private
RPO copy, `*-current.txt` pointer or scratch script is a project dependency.
`out/` contains generated deliverables; `.deps/` is the managed dependency cache.

| Input or result | Durable location |
| --- | --- |
| Product and addon sources | `src/`, `addons/` |
| Test programs, SQL fixtures and reproducible probes | `tests/` and `src/tlpp/tests/` |
| Build/test/maintenance entry points | `scripts/` |
| Public configuration templates and dependency pins | `config/examples/`, `config/dependencies.json` |
| Accepted scope, counts, methodology and limitations | `docs/acceptance.md` and summaries here |
| Licenses, SDK/RPO, private credentials/INI and databases | Explicit external prerequisites; never version these copies |
| Build objects, generated HRBs, copied RPOs, logs and reports | Disposable `tmp/`/`out/`; optional deliberate external archive |

These identities describe the dated source snapshot, not today's checkout.
Historical `tmp/...` mentions in older records identify where output was written;
they neither guarantee that it still exists nor prevent its deletion. A new
execution creates a new observation/log. Exact historical timing or machine state
cannot be regenerated by replaying the source. Preserve raw evidence externally
only when that history itself is required; it is not a build prerequisite.

## Reproduce from sources

Resolve the [pinned dependencies](../dependencies.md), then run the maintained
entry points. Every runner creates its current scratch directories itself:

```powershell
./scripts/bootstrap.ps1
./scripts/build-hbbridge.ps1
./scripts/test-hbbridge.ps1
./scripts/test-harbour-thread-state.ps1
./scripts/test-harbour-sqlite-bind.ps1
./scripts/test-hbbridge-typed-sql.ps1
./tests/unit/scripts/clean.artifacts.test.ps1
./scripts/check-doc-links.ps1
./scripts/commit-check.ps1
```

The MSSQL checks additionally require the configured driver, an accessible
database and a private INI prepared from the public examples. Supply the path
and explicit alias; no prior test directory is an input:

```powershell
./scripts/test-hbbridge-mssql.ps1 -Config '<private-ini>' -Profile '<alias>'
./scripts/test-harbour-mssql-bind.ps1 -Config '<private-ini>' -Profile '<alias>'
./scripts/test-hbbridge-typed-sql.ps1 -Config '<private-ini>' -Profile '<alias>'
./scripts/test-hbbridge-mssql.ps1 -Config '<private-ini>' -Profile '<alias>' -Integrity
./scripts/test-hbbridge-mssql.ps1 -Config '<private-ini>' -Profile '<alias>' -Failures `
    -FailureODBCDriver 'ODBC Driver 18 for SQL Server'
./scripts/test-hbbridge-mssql.ps1 -Config '<private-ini>' -Profile '<alias>' -Concurrency
./scripts/test-hbbridge-mssql.ps1 -Config '<private-ini>' -Profile '<alias>' -Pooling -ODBCPooling driver
./scripts/test-hbbridge-benchmark-addon.ps1
node --test ./tests/unit/browser/hbbridge.benchmark.page.test.mjs
```

AppServer tests require the licensed SDK/RPO and an explicitly configured test
environment. Compile the current `src/tlpp` using `build-totvs.cmd` and its
documented installation/include arguments. Use a dedicated test INI with its own
ports and compiled RPO, then run the versioned launcher:

```powershell
./scripts/run-protheus-cli.ps1 -AppServerDirectory '<test-appserver>' `
    -IniFile '<dedicated-test-ini>' -Program U_HBBridgeJSONTest
```

Other closed suites include `U_HBBridgeDataSetTest`, `U_HBBridgeHelperTest`,
`U_HBBridgeHTTPTableTest`, `U_HBBridgeBenchmarkVisualTest` and
`U_HBBridgeBenchmarkRESTTest`; `U_HBBridgeBenchmarkControlTest` covers route,
statistics and timeout controls without a live SQL service. The launcher reports
the actual exit code and
log path, without guessing assertion success. Some procedure entries return
-4 without a numeric CLI return; inspect their complete assertion summaries.
It never replaces an INI/RPO or stops an existing service. Its timeout applies
only to the child it starts. INI content and argument values are not copied
into its receipt; raw output remains local scratch.

For real TCP/HTTP integrity, start the maintained MSSQL runner with `-Integrity
-Serve` in another terminal and pass that live run's endpoints to
`U_HBBridgeIntegrityCLI` via the launcher's `-Argument` array. Ports/tokens from
an old run are not reusable prerequisites. See [D03](../dataset.md) and each
test's README for the complete contract and manual UI scenarios.

For the real TLPP client-to-HRB benchmark regression without SQL credentials,
start `scripts/test-hbbridge-benchmark-addon.ps1 -Serve -ServeSeconds 600` in
another terminal. Its freshly generated fixture reports its current TCP port,
profile and module. Configure that module in the dedicated AppServer test INI,
then run `U_HBBridgeBenchmarkCLI` with explicit `--routes=hbbridgeAddon`, the
reported endpoint/profile, `--rows=1 --page-size=1`, and the desired iteration
and warmup counts. This validates the actual transport and addon with a mock
query handler; it does not validate MSSQL. Real SQL benchmarking requires the
private database configuration described in [benchmarking](../benchmarking.md).
